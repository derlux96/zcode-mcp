# v1.1 Model Selection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add per-call model selection to `zcode_run` via a dual-mode runner — official `-p` path unchanged (mode A), internal app-server protocol when `model` is set (mode B) — so the plugin works on any provider configuration.

**Architecture:** New module `src/appserver.mjs` owns ALL protocol knowledge (child spawn, line framing, id-correlated requests, auto-answering server requests, turn event collection). `src/mcp-server.mjs` routes: `model` param set → mode B, else mode A (v1 code untouched). Deterministic protocol tests via `test/fake-appserver.cjs`.

**Tech Stack:** Node ≥18 ESM, zero npm deps, `node:test`.

**Spec:** `docs/superpowers/specs/2026-10-17-v1.1-model-selection-design.md`
**Protocol evidence (REQUIRED READING for Task 1):** `.superpowers/v1.1/protocol-notes.md` — contains the exact wire shapes (envelope, session/create params, modelSelection, event sequence, server-request trap). Transcribe shapes from there, not from memory.

## Global Constraints

- Zero npm dependencies; Node ≥18 ESM; stdout of OUR server stays protocol-only.
- All app-server protocol code lives in `src/appserver.mjs` — runner.mjs/mcp-server.mjs must not import child_process for protocol purposes.
- Mode A (`-p` path) code paths unchanged in behavior.
- `options.reasoningLevel` is REQUIRED at send time (protocol rejects without it) — enum `low|medium|high|max`, default `high`.
- The app-server sends its own requests (e.g. `session/requestRuntimePreferences`, ~15 s timeout); unanswered ones hang session/create — the client MUST answer unknown server requests with `{id, result: {}}` and known ones with their documented result shape.
- Never write to user configs. Spawn only argument-array children.
- Session IDs from mode B are real `sess_…` ids (resumable via mode A `--resume` as well).

### Task 1: `src/appserver.mjs` + fake app-server + tests

**Files:**
- Create: `src/appserver.mjs`, `test/fake-appserver.cjs`, `test/appserver.test.mjs`

**Interfaces (Produces):**
- `class AppServerClient` — constructor `({ binPath, cwd, timeoutMs = 30000, spawnFn })`; method `request(method, params, { timeoutMs }) → Promise<result>` (rejects on `error` responses / timeout / child death); handles server-initiated requests via `_handleServerRequest` (answers `session/requestRuntimePreferences` with `{nativeSearchEnhancementsEnabled:false}` per protocol notes; anything unknown → `{}`); collects `session/event` notifications into an event buffer; `close()` kills the child.
- `export async function runTaskWithModel({ binPath, cwd, prompt, providerId, modelId, reasoningLevel = 'high', timeoutMs = DEFAULT_TASK_TIMEOUT_MS }) → { ok, sessionId, response, failed, error }`:
  1. spawn client; wait for startup notifications to settle (per notes: a short quiet window or ready signal — use what the notes say)
  2. `session/create` with `workspace: { workspacePath: cwd, workspaceKey: cwd }` → capture `sessionId` + model catalog (`settings.model.available`, if present)
  3. `session/send` with prompt + `modelSelection: { providerId, modelId, options: { reasoningLevel } }`
  4. await `turn.completed` (`payload.response` = final text) or `turn.failed` (→ `ok:false`, error from payload) within timeoutMs
  5. `close()`; return result
- `export function resolveModel(catalog, modelSpec) → { providerId, modelId } | null` — accepts `"modelId"` (search catalog for a provider offering it; first match) or `"providerId/modelId"` (exact). Catalog shape per protocol notes.

**Test fake (`test/fake-appserver.cjs`)** — a node script speaking the server side, controlled by `FAKE_APPSERVER_MODE`:
- `ok`: startup noise → answers create (sessionId `sess_fakeB1`, catalog with two providers) → echoes server-request `session/requestRuntimePreferences` (must be answered — the fake FAILS the connection after 2 s if not, proving the trap handling) → acks send → emits `session/event turn.completed` with `payload.response: "fake model task done"`.
- `fail`: same, but `turn.failed` with `payload.error.message: "fake model failure"`.
- `slowhang`: never emits the turn event (timeout path).
- Protocol shapes copied verbatim from `.superpowers/v1.1/protocol-notes.md`.

**Tests (test/appserver.test.mjs):** happy path (sessionId + response), turn.failed → ok:false with error, timeout kills child + rejects, server-request trap answered (fake enforces it), resolveModel both syntaxes + unknown → null, child-death mid-request → clean rejection. TDD: red first (module missing), then green.

Run: `node --test test/appserver.test.mjs`, then `npm test` (must stay green, now incl. new suite). Commit: `feat: app-server protocol client with model selection (mode B core)`.

### Task 2: Wire `model`/`reasoning_level` into `zcode_run` + `include_models` into `zcode_check`

**Files:**
- Modify: `src/mcp-server.mjs` (schema + handler routing), `test/tools.test.mjs`

**Interfaces (Consumes):** Task 1 exports. **Produces:** extended `zcode_run` schema:
- `model` (string, optional, description covers both syntaxes; setting it switches to protocol mode)
- `reasoning_level` (enum, optional, default high, mode B only)
- `zcode_check` gains `include_models` (boolean, optional, default false) → appends `models:` section from a throwaway create-catalog (best-effort, 15 s timeout; on failure a `[warning] models unavailable` line).

**Handler routing in `zcode_run`:**
- validate: `model` string or absent; `reasoning_level` in enum.
- if `model` set: `resolveModel` needs the catalog → obtained from mode-B create response. Flow: open AppServerClient once; create; resolve `model` against returned catalog (unresolvable → isError with the available models listed); send with reasoningLevel; collect turn outcome; state entry (kind `session`, real sess_ id); worktree isolation still applies (cwd = worktree dir); result text mirrors mode A shape (`status:`, `session_id:`, output markers) so the skill/agent contract stays uniform.
- mode A path byte-identical to v1.

**Tests (test/tools.test.mjs):** with `ZCODE_APPSERVER_BIN` env override pointing at the fake (Task 1 fake accepts a binPath injection — implementer: read binPath from `process.env.ZCODE_APPSERVER_BIN ?? discoverZCode()` inside appserver.mjs so tests can stub it):
- mode B happy: `model: "glm-test/small"` resolves via fake catalog → `status: completed`, `session_id: sess_` real.
- unresolvable model → isError listing available.
- `reasoning_level` invalid → validation error.
- mode A regression: no model param → identical behavior to v1 tests (existing tests must pass unmodified).
- `zcode_check {include_models:true}` → models section present (fake), `include_models` absent → no section, fast.

Run: `node --test test/tools.test.mjs`, `npm test`. Commit: `feat: model and reasoning_level params on zcode_run, include_models on zcode_check`.
